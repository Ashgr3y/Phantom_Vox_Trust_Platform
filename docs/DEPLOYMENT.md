## Current status

The deployment copy is prepared and tested locally and published at https://github.com/Ashgr3y/Phantom_Vox_Trust_Platform. A Free-only Render Blueprint has been submitted without adding a payment method. Cloud build, inference, HTTPS flow and persistence checks are still pending; do not put an unverified URL in the PPT.

Hosting and database credentials are not committed.

## Architecture inspected

- Frontend: React 18, TypeScript, Vite 6, Tailwind CSS, React Router, React Query, Recharts. Node dependencies install from the existing lockfile.
- Backend: Python 3.12, FastAPI, Uvicorn, SQLAlchemy, Alembic, bcrypt/JWT authentication, authenticated WebSockets.
- Database: local SQLite by default; public deployment uses Render managed PostgreSQL with the installed psycopg 3 driver. Provider `postgresql://` URLs are normalized to `postgresql+psycopg://`.
- ML: included RawNetLite Conv1D residual/BiGRU architecture and 987,460-byte checkpoint. CPU PyTorch, NumPy and SoundFile are included in the cloud image. Checkpoint SHA-256: `44f5483b514902fb7698654d03c55c98aef128075c2310ba8b94f1f770449028`.
- Docker: Node frontend build stage and Python runtime stage. The Python backend serves `frontend/dist`, REST and WebSockets through one host. One process/instance preserves the existing in-process demo task and socket hub.
- Communication: frontend defaults to relative `/api/v1`; WebSockets derive `wss://` from the HTTPS website origin. No Vite URL overrides are needed. Local Vite proxy and optional Windows loopback adapter are development tools and are not cloud dependencies.
- Routes: `/auth/login`, `/health`, `/health/models`, `/dashboard/summary`, `/sessions` and audio upload, `/demo`, `/incidents`, `/policies`, `/trusted-voices`, `/transactions`, `/verifications`, `/audit`, `/models`, `/evaluations`, `/integrations`, `/notifications`, and `/ws/sessions/{id}`, all under `/api/v1`. See API_GUIDE.md and generated OpenAPI for the full route map.

## Provider and configuration

Use the included `render.yaml` Blueprint: Singapore, one Free Docker web service and Free managed PostgreSQL. Never add a payment method, upgrade a plan or create a paid resource for this deployment. The Free web service sleeps after 15 idle minutes and has 512 MB RAM; actual ML memory behavior must be verified in the cloud. The Free database expires after 30 days and has no backups. Render assigns the actual HTTPS URL; the service name does not guarantee an identical hostname.

Environment variables configured by the Blueprint:

| Variable | Value / source |
|---|---|
| `PHANTOM_VOX_ENVIRONMENT` | `production` |
| `PHANTOM_VOX_DATABASE_URL` | Managed database internal connection string, supplied by Render |
| `PHANTOM_VOX_JWT_SECRET` | Random value generated by Render; never commit or paste into chat |
| `PHANTOM_VOX_CORS_ORIGINS` | `[]`; the website and APIs share one origin, so cross-origin access is unnecessary |
| `PHANTOM_VOX_DEMO_MODE` | `true` |
| `PHANTOM_VOX_SEED_DEMO_DATA` | `true`; seed occurs once on a new database |
| `PHANTOM_VOX_REQUIRE_ML` | `true`; startup must load checkpoint and complete a finite forward pass |
| `PHANTOM_VOX_RETAIN_RAW_AUDIO` | `false` |
| `PORT` | Supplied automatically by Render |
| `OMP_NUM_THREADS`, `MKL_NUM_THREADS` | `1`, set in Docker image |

Leave `VITE_API_URL` and `VITE_WS_URL` unset for this architecture. If a separate frontend is ever introduced, explicitly configure its HTTPS origin in the CORS JSON array and use HTTPS/WSS API URLs.

The managed database is restricted to internal connections (`ipAllowList: []`). A container restart does not erase its records. Production rejects SQLite and placeholder JWT signing secrets. Health probes verify database access and required ML loading.

## Account sign-in and deploy steps

1. Sign in to GitHub and Render in the Codex browser; complete OAuth/MFA yourself. Never provide account passwords, access tokens or database passwords in chat.
2. Use https://github.com/Ashgr3y/Phantom_Vox_Trust_Platform with this prepared directory at its root. If publishing the enclosing SIH_1 repository, set the Blueprint path to `Phantom_Vox_Trust_Platform/render.yaml` and the service root directory to `Phantom_Vox_Trust_Platform` instead.
3. In Render choose **New > Blueprint**, connect that repository, and select the included YAML. Grant repository access only as needed.
4. Confirm BOTH plans are Free. If Render requests billing, stop; do not add a card or create paid resources.
5. Wait for both resources and the Docker build to succeed. Review startup logs for successful application startup. A model or database failure must be fixed before accepting the deployment.
6. Open the service's assigned HTTPS URL, confirm health, and test login/dashboard/Live Guard/upload/Model Trust/Privacy & Audit.
7. Run `python scripts/check_deployment.py https://YOUR-ASSIGNED-HOST` from a cloud runner with the script and dependencies available (Free Render does not provide a shell). It checks HTML/deep links, login, dashboard, authenticated WebSocket delivery, transaction hold/verification/incident, actual ML upload, and audit integrity. It creates fictional test metadata. It never prints authentication tokens.
8. Restart the service and verify the recorded session/incident still exists. Repeat a real audio upload and confirm model status is active.

## Remaining limitations and PPT checklist

Judge scenarios simulate multi-evidence decisions; uploaded audio runs real RawNetLite. Upload scores are displayed separately and do not replace the simulated scenario timeline. AASIST, speaker verification, SMS, telephone adapters and real banking integrations remain unimplemented/demo-only. No verified accuracy or calibration claim is available. Retention scheduling, enterprise identity, distributed processing and high availability are outside this judge-demo deployment. Several existing UI privacy cards describe intended controls rather than implemented cloud guarantees; use KNOWN_LIMITATIONS.md when presenting.

Before adding the URL to the PPT:

1. Complete cloud deployment and save the exact assigned HTTPS URL.
2. Pass the cloud smoke check, browser upload check with your consented speech samples, and persistence-after-restart check.
3. Open that HTTPS URL in a signed-out/incognito browser and on a phone using mobile data.
4. Confirm the prefilled demo login, dashboard, **Mid-call clone** workflow, displayed upload score, **Model Trust** loaded status and **Verify audit integrity** action.
5. Confirm the Free database expiry is AFTER judging. Open the website several minutes before presenting to wake the Free service, then test login and upload again. Retain an offline screen recording as backup.
6. Insert a clickable HTTPS link (and optionally a QR code) into the PPT. Never insert localhost or any URL containing an authentication token.
